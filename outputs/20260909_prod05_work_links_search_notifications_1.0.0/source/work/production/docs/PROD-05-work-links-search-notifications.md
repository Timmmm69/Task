# PROD-05 — файлы, контакты, поиск и уведомления

Версия реализации: 1.0.0.

## Результат

Production Windows-клиент больше не показывает заглушки для каталога, контактов, поиска и
уведомлений. После входа каждый раздел загружает только разрешённые сервером данные и использует
существующие API-04/DATA-04 контракты без параллельного локального источника истины.

- Каталог показывает записи файлов, создаёт file reference, регистрирует локальный или разрешённый
  UNC path и открывает выбранный файл после отдельного server resolve.
- Контакты отображаются и создаются в общем каталоге, после чего доступны существующим object-link,
  calendar attendee и search сценариям.
- Глобальный поиск возвращает permission-filtered метаданные задач, проектов, контактов и файлов;
  результат маршрутизирует пользователя в соответствующий рабочий раздел.
- Центр уведомлений показывает собственные уведомления, непрочитанный счётчик, mark-read и
  ограниченный серверным контрактом bulk read (не более 500 UUID за команду).

## Файловая граница

Приложение не читает и не проксирует содержимое рабочего файла через сервер. Открытие начинается
только по явной команде пользователя: сервер выбирает доступный location для текущей session/device,
desktop повторно проверяет fully-qualified path и существование, запрещает запуск executable/script/
shortcut типов и передаёт безопасный путь Windows Shell. Отсутствующий путь, отказ ACL и Shell error
показываются раздельно. Автоматический поиск перемещённых файлов и сканирование диска отсутствуют.

## Доступ и ошибки

Capabilities управляют только доступностью элементов UI; сервер повторно проверяет permission и
object scope. Все запросы проходят существующий authenticated executor с single refresh. Клиент
ограничивает размеры ответов, строго валидирует обязательные поля, использует strong ETag для
location write и idempotency keys для create/bulk/resolve команд. `401`, `403`, `404`, validation,
conflict и transport failure переходят в контролируемые русскоязычные состояния.

## Проверка и границы приёмки

Автотесты покрывают canonical URI, bearer/ETag/idempotency headers, строгий mapping и malformed/
forbidden ответы, capability gating, file resolve-before-open, search navigation и unread state.
Существующие service-host и PostgreSQL contract suites подтверждают route policies и API semantics.
Новая миграция не требуется. Live PostgreSQL smoke, реальное SMB/ACL окружение и native Windows
UIA/Narrator walkthrough остаются deployment acceptance на стенде заказчика.
