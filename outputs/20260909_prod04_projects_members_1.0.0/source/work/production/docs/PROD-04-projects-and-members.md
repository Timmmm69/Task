# PROD-04 — проекты и участники

Версия реализации: 1.0.0.

## Результат

Раздел «Проекты» в production Windows-клиенте больше не является заглушкой. После входа он
загружает только разрешённые сервером проекты и показывает карточку выбранного проекта, статус,
сроки, владельца, руководителя, активных участников с проектными ролями и связанные задачи.

Пользователь с соответствующими capabilities может создать или изменить проект, перевести его в
один из контрактных статусов, архивировать завершённый проект, добавить участника, изменить его
роль или удалить участника. Владелец не удаляется через операцию участника: сервер требует сначала
выполнить отдельную передачу владения.

## Контракт и безопасность

- Все чтения и команды выполняются через authenticated executor; `401` проходит существующий
  single-refresh flow, а terminal auth failure переводит поверхность в безопасное состояние.
- UI использует capabilities только для presentation. Каждый endpoint сохраняет серверную policy и
  object/project-scope проверку.
- Записи не применяют optimistic state: UI меняется только после authoritative response.
- Изменения передают strong `If-Match`; create/add/change/archive используют idempotency key.
- `403`, `404`, `412`, validation/state conflicts и transport failure отображаются как ограниченные
  безопасные состояния без раскрытия серверных деталей.
- Новый канонический `GET /api/v1/project-roles` доступен по `Project.Read`. Он возвращает только
  активные роли с project permissions; административные и не назначаемые обычным руководителем
  роли отфильтрованы сервером.

## Связанные задачи

Клиент использует существующий типизированный Task API, проходит cursor pagination и оставляет
только задачи, чья карточка содержит выбранный `projectId`. Это сохраняет единый контракт задач и
не вводит параллельный endpoint. При отсутствии `Task.Read` блок связанных задач остаётся пустым и
не раскрывает данные.

## UX-границы

Текущий User API не гарантирован capability `Project.ManageMembers`, поэтому форма участника не
делает скрытый обход каталога сотрудников: она принимает UUID активной учётной записи, а сервер
проверяет tenant и active status. Отображение ФИО и entity-picker остаются отдельным улучшением
общего каталога сотрудников и не влияют на работоспособность операций PROD-04.

## Проверка

Автоматизированы строгий mapping project API, canonical URI и headers, controlled failures,
capability gating, загрузка ролей/участников/связанных задач, создание и изменение версии после
membership command. Route-policy suite проверяет deny-before-store для всех product endpoints,
включая `GET /api/v1/project-roles`.

PostgreSQL runtime не изменялся миграцией: endpoint читает уже существующие `iam.roles` и
`iam.role_permissions`. На машине сборки Docker/PostgreSQL недоступны; это честно отражено в
validation report. Ранее подтверждённый API-04 PostgreSQL gate остаётся базой для существующих
project/member write paths.
