# Task 1.0.7 — portable Windows x64

Это проверенный **unsigned portable candidate**. Полная production-приёмка пока
BLOCKED: чистая Windows без установленного современного .NET, физический offline
и видимое Windows notification popup не проверены. Точные результаты — в
`validation-report.md`. Code-signing certificate для этого варианта не требуется.

## Запуск

1. Получите ZIP и SHA-256 из доверенного источника. В PowerShell выполните
   `Get-FileHash .\Task-1.0.7-win-x64-unsigned.zip -Algorithm SHA256` и сравните с
   `SHA256SUMS`. Manifest дополнительно содержит hashes всех семи файлов приложения.
2. Распакуйте ZIP в отдельную папку. Запустите `Task\Task.Desktop.exe`.
   Установка сервиса, SDK или отдельного .NET не предусмотрена: сборка self-contained.
   Фактический запуск на чистой Windows ещё требует acceptance.
3. При первом запуске выберите **Personal** или **Corporate**. Выбор запоминается;
   кнопка смены режима позволяет изменить его позже. Сохраните открытые формы либо
   явно отмените их; переключение не означает автоматического сохранения.

**Personal** работает с локальными задачами, проектами, календарём, повторениями,
контактами, каталогом и напоминаниями без корпоративного входа. Уведомления зависят
от работы Task в фоне и настроек Windows; видимый popup пока не принят проверками.
Данные находятся отдельно от программы: `%LOCALAPPDATA%\Task\Personal\tasks.db`.

**Corporate** требует действительного HTTPS-сервера компании, доверенной цепочки
сертификата и корпоративного входа. Адрес и учётные данные предоставляются компанией.
При отсутствии соединения корпоративная запись недоступна; локальной очереди записи
нет. Personal и Corporate имеют раздельные данные. Сеанс Corporate защищается
существующим Windows credential vault. Не отключайте TLS или проверку сертификата.

`TASK_DESKTOP_DATA_DIRECTORY` — необязательная настройка отдельного абсолютного
каталога данных. Не указывайте папку приложения. При обновлении используйте тот же
каталог данных и того же пользователя Windows; перенос credentials между машинами
не является supported backup. Поставка не содержит готовой БД или accounts.

## Backup и restore

В Personal откройте «Настройки» → «Резервные копии и работа в фоне».
Создайте `.taskbackup` вне папки приложения и вне `Personal`; дождитесь сообщения
об успешной проверке и сохранении. Записи каталога входят в backup, физические файлы
по их путям копируйте отдельно. Corporate credentials и PostgreSQL не включаются.

Для restore сначала сохраните/отмените формы, выберите backup и подтвердите замену.
Текущая БД сохраняется как safety copy в `Personal\recovery\restore-<id>`.
Повреждённый, обрезанный или несовместимый backup отвергается без замены текущей БД.
При recovery-окне сохраняйте исходную БД и sidecars; используйте проверенный backup
или «Вернуть safety copy», если это действие доступно. Не удаляйте единственную БД.
Recovery copies автоматически не очищаются. Подробности — `personal-backup-recovery.md`.
Для Corporate backup/restore выполняет администратор сервера по его runbook.

## Ручное обновление

1. Проверьте SHA-256 нового ZIP. Создайте и проверьте Personal backup вне программы.
2. Закройте все Task-процессы. Сохраните предыдущую папку приложения отдельно.
3. Распакуйте новый ZIP в новую папку или замените только файлы приложения.
   Сохраните `%LOCALAPPDATA%\Task` либо прежний явно заданный каталог данных.
4. Запустите новый EXE; проверьте задачи, поиск, повторения и новый backup, затем
   Corporate вход на предназначенный HTTPS-сервер. Не переносите тестовые данные.
5. При сбое миграции сохраните БД и recovery copies. Старый EXE может отвергнуть
   новую схему: возврат бинарников не означает откат данных. Используйте процедуру
   recovery, не перезаписывайте единственную БД.

Unsigned ZIP не предназначен для существующего signed auto-updater. Signed pipeline
сохранён. Возможные Windows/SmartScreen предупреждения не обходятся автоматически;
их поведение на чистом образе Windows пока не подтверждено.
