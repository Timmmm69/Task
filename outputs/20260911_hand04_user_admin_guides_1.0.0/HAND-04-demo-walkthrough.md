# HAND-04 Синтетический demo набор и маршрут приёмки

Версия: 1.0.0. Этот маршрут служит для передачи инструкций, обучения и повторной проверки на чистом стенде. Он опирается на уже проверенный QA-03 профиль `qa03-deterministic-v1`: свежий PostgreSQL 16, production HTTPS API, production Worker и реальный Release WPF. Все данные, сертификаты, секреты и учётные записи в нём синтетические и детерминированные.

## Роли demo набора

| Маркер роли | Роль | Что демонстрирует |
| --- | --- | --- |
| `admin` | `system_administrator` | Вход и административный контроль учётной записи, сессий и прав через защищённый API. |
| `manager` | `system_manager` | Создание проекта, задачи и работа с участниками в разрешённой области. |
| `employee` | `system_employee` | Назначенная работа, создание и изменение доступной задачи, календарь и уведомления. |
| `observer` | `system_observer` | Доступное чтение и отказ в командах создания. |

Названия и пароли тестовых учётных записей намеренно не включены в пакет: QA-03 создаёт их в изолированной среде и очищает при завершении. Это не production seed и не импортируемый набор данных.

## Предусловия

- Windows с PowerShell 7, .NET 10, PostgreSQL 16 и возможностью запускать WPF/UI Automation;
- чистая локальная рабочая область Task; `TASK_DESKTOP_DATA_DIRECTORY` изолирован runner-ом;
- доступ к исходному дереву и зависимостям, описанным в `work/production/verification/Test-Qa03Gate.ps1`;
- запуск выполняет инженер с правом создавать только временный localhost PostgreSQL/API runtime.

Не запускайте этот маршрут против production и не направляйте его на корпоративный сервер, DNS или secrets manager.

## Воспроизведение

Из корня репозитория выполните:

```powershell
pwsh -NoProfile -File work/production/verification/Test-Qa03Gate.ps1 -EvidenceDirectory outputs/20260910_qa03_critical_e2e_1.0.0/evidence
```

Runner собирает Release solution, поднимает изолированный HTTPS API и рабочий процесс, подготавливает demo-данные, проводит UI Automation и удаляет созданный runtime. При успешном завершении проверьте `outputs/20260910_qa03_critical_e2e_1.0.0/evidence/qa03-gate.log`, JSON assertion-ы и скриншоты. Не заменяйте проверку ручным «похожим» запуском с mock-данными.

## Маршрут для инструктора

1. Войдите synthetic-пользователем и покажите, что рабочая оболочка открывается только после HTTPS-входа и подтверждения сессии.
2. Откройте «Сегодня» и «Календарь»: убедитесь, что отображаются засеянные задачи, события и повторения.
3. В «Задачах» создайте запись, откройте её и измените. Затем воспроизведите конкурентное изменение: Task должен сохранить локальный черновик, загрузить серверную версию и потребовать явного повторного сохранения.
4. В «Проектах» покажите список, карточку и участника. Для manager продемонстрируйте создание проекта/задачи только в доступной области.
5. Откройте «Каталог», «Контакты» и «Поиск». Покажите, что поиск возвращает только разрешённые метаданные, а файл открывается только после server resolve и проверки Windows.
6. Откройте «Уведомления» и отметьте уведомление прочитанным. Подтвердите delivery в evidence worker-а.
7. Войдите observer-ролью и попытайтесь создать проект или задачу. Ожидаем отказ без побочного изменения данных.
8. Остановите API через предусмотренную QA-03 фазу. Убедитесь, что подтверждённые данные остаются видимыми, команды записи отключены, а черновик не отправляется. Запустите API, выполните явное обновление и сохраните черновик вручную.
9. Завершите runner и убедитесь, что его cleanup завершился успешно. Сохраните только разрешённые evidence-файлы; не сохраняйте секреты, токены или локальный credential vault.

## Критерии готовности к передаче

Маршрут считается пройденным, когда QA-03 фиксирует `real_wpf_https_postgresql: PASS`, `conflict_recovery: PASS`, `offline_shell_and_reconnect: PASS`, отказ read-only роли при создании и `cleanup: PASS`. Эталонный пакет `outputs/20260910_qa03_critical_e2e_1.0.0` уже содержит эти результаты. Customer-specific сетевые имена, корпоративный CA, SMB ACL, реальные устройства и формальная приёмка остаются post-handoff действиями заказчика.
