# Сотрудники WPF — 11.2.0

Реализованы создание и редактирование в существующем административном разделе.
Ветка `feature/admin-user-management`, основа — коммит 11.1 `4c737b2` поверх
актуального на начало работы `origin/main` (`2f50889`). Основная рабочая копия
с несвязанными незакоммиченными изменениями не затронута. Публикация в main не выполнялась.

## Операции и права

- Использован существующий `DesktopAdministrationApiClient`; второй клиент, API,
  серверные DTO и зависимости не добавлены.
- Список перешёл на типизированные cursor-страницы. Слева имя, login и статус;
  справа подтверждённая карточка или редактор с отдельными «Сохранить»/«Отмена».
- `User.Read` открывает данные раздела; `User.Create` отдельно разрешает POST;
  `User.Update` отдельно разрешает свежий GET записи и PATCH. Наличие только
  User.Read блокирует обе операции. Сервер сохраняет окончательную проверку прав.
- Создание: имя, фамилия, login обязательны; displayName необязателен и при
  отсутствии формируется сервером. Email и должность необязательны. Проверены
  серверные длины, формат email, required/optional. Статус и пароль не вводятся.
- Серверный POST создаёт `pending_activation`. После подтверждённого ответа
  обновляется список и выбирается новая запись, даже если она вне первой страницы.
- Редактор заново читает запись, заполняется её данными и отправляет сохранённую
  свежую версию через существующий If-Match. PATCH содержит только затронутые поля.
  Очистка nullable email/должности отличается от отсутствия поля в PATCH.
  DepartmentId, роли и статус сохраняются без вмешательства редактора.
- Сохранение защищено от второго нажатия; поля, выбор записи и отмена заблокированы
  во время запроса. Неопределённый результат замораживает исходный запрос/ключ;
  повторная отправка возможна только явно и с теми же параметрами. Локальной очереди нет.
- 412 сохраняет ввод и блокирует слепой повтор. Пользователь может скопировать
  изменения и отменить/переоткрыть запись. Автоматического перезаписывания нет.
- Обработаны loading, empty, error, forbidden, offline, read-only, validation,
  version conflict, unavailable и session expired. При отзыве User.Read/завершении
  сессии защищённые данные очищаются. Поздние ответы чтения не открывают чужой редактор.

## Ограничения и обнаруженные дефекты

- Сервер возвращает один `DUPLICATE_RESOURCE` для login и workEmail без поля.
  UI выделяет этот случай из остальных ошибок и просит проверить оба поля.
  Определить, какое именно поле занято, достоверно нельзя без изменения контракта.
- Подтверждённого API выбора подразделения по имени нет: UUID не запрашивается,
  создание оставляет подразделение пустым, редактирование сохраняет существующее.
- Создание **не означает готовность сотрудника ко входу**. API не возвращает пароль;
  отдельный процесс активации/получения учётных данных остаётся зависимостью.
  Новый invitation/password workflow не создавался.
- Выявлены и покрыты регрессиями: поздний detail/list после смены selection/прав,
  потеря подтверждённого receipt при неизменившихся capabilities, ошибка refresh
  после успешной записи, сохранение исходного ключа после неопределённого результата.
- Унаследованный нестабильный тест системного фокуса оставляет общий gate открытым.
- Live Corporate API/реальная БД, ручной Narrator и физическая DPI-матрица в этом
  этапе не проверялись. Подключённая корпоративная сессия для ручной проверки не использовалась.
