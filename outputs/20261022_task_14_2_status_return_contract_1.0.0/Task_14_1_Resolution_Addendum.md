# Task 14.1 — дополнение о закрытии противоречия

Дата: 22.10.2026. Версия дополнения: 1.0.0. Baseline main: `fa504bc01584547afc50398ba6c1735391c4173c`.

Исходный аудит 14.1 v1.0.0 зафиксировал CONTRACT_CHANGE_REQUIRED из-за прямого противоречия implementation prompt каноническому review→in_progress. Сам финальный OpenAPI уже содержал нужную operation и DTO. Этот статус не означал необходимости нового endpoint или изменения схемы.

После поручения пользователя «сделай всё лучшим образом, я доверяю» выбран вариант применения существующей канонической модели. DEC-14-RETURN-001 в соседнем контракте 14.2 заменяет только противоречащий запрет возврата в историческом prompt. Исторические файлы и аудит не переписаны.

Принятый минимальный сценарий: Task.ChangeStatus + existing object scope; причина необязательна, отдельного ввода причины в новой кнопке нет (reason=null); обязательного Comment.Create и нового notification type нет. Действуют существующие audit/event/outbox/concurrency/idempotency. Дополнительные reviewer restrictions не вводятся.

OQ-14.1-01 закрыт документарным решением. Для OQ-02–04 зафиксирован существующий минимальный baseline; его расширения не входят в сценарий. OQ-05 и связанные общий API/history drift и terminal workflows остаются отдельно открытыми.

Текущий статус выбранного бизнес- и API-сценария: **READY**. Это разрешает переход к отдельному этапу реализации по контракту 14.2; не означает готовность production-функции. Production-код не изменён; main всё ещё отклоняет review→in_progress. Исходное ограничение задачи на изменения production-кода сохраняется.
