## Компоненты

- `ProjectDetailSectionViewModel`: контекст ProjectId/OrganizationId, CanRead, HasConfirmedData,
  состояния и безопасный текст, один принадлежащий разделу запрос. BeginRequest отменяет
  предыдущий запрос; IsCurrent проверяет владельца запроса, token и проект; FinishRequest
  освобождает ссылку, фактический async-владелец выполняет Dispose.
- `ProjectsViewModel.Sections.cs`: шесть владельцев состояния, смена контекста, общая отмена,
  загрузка участников и их ролей через существующий IDesktopProjectsApiClient.
- `ProjectsViewModel.cs`: прежний orchestration и команды. IsDetailLoading относится к
  подтверждению обзора. CurrentDetailsOperation оставлен совместимым: ожидает также
  первоначальную загрузку участников/имён; UI не обязан ждать эту операцию для задач.
- `ProjectsViewModel.RelatedTasks.cs`: прежние cursor/request/generation правила;
  TasksSection отображает существующий ProjectTasksState без второго загрузчика.
- `ProjectsView.xaml`: основные сведения, участники и задачи — обычные WPF Expander.
  Существующие ключи preferences сохранены; добавлен `projects/v1/overview` в allowlist.
  Persistence хранит только раскрытие; идентификаторы проектов и данные не записываются.
- FilesSection, ContactsSection, HistorySection: изолированные неподключённые точки расширения
  с актуальным контекстом. IsConnected/CanRead=false; состояния NotLoaded, без запросов и
  без декоративных UI-заглушек. Это не реализованные разделы файлов/CRM/истории.

## Состояния и доступ

| Состояние | Правило |
|---|---|
| NotLoaded | Запрос не выполнялся; также неподключённый функциональный раздел |
| Loading | Выполняется текущий запрос только данного раздела |
| Loaded | Подтверждённый ответ с доступными данными |
| Empty | Только успешный полный пустой ответ; ошибки не превращаются в пустоту |
| Forbidden | Нет capability, либо сервер отказал в чтении раздела; защищённые данные очищаются |
| Offline | Сеть отключена; ранее подтверждённые данные в текущем контексте остаются read-only |
| ServerUnavailable | Ошибка транспорта/API; подтверждённые данные текущего раздела сохраняются |
| Error | Некорректный ответ или иная ошибка; безопасный текст без содержимого исключения |
| PartialAccess | Роли/имена недоступны при доступном составе участников; у задач также неполная страница поиска |
| Cancelled | Прерванная загрузка; поздний результат не публикуется |

Обзор требует Project.Read. Чтение участников требует Project.Read и Project.ManageMembers:
именно такая policy действует у GET `/projects/{id}/members`, несмотря на write-only описание
в старом UX baseline SCR-064. Имена отдельно требуют User.Read; отсутствие права не запускает
User API. Задачи требуют Project.Read, Task.Read и существующий typed Tasks client.
Записи дополнительно требуют активную сессию/экран, online и соответствующую существующую
capability. Никаких permissions, маршрутов, DTO или бизнес-статусов не добавлено.

403 состава участников очищает только состав; не запрещает чтение/редактирование обзора
или задачи. Terminal authentication failure завершает всю сессию. Отзыв права чтения,
закрытие карточки, смена ProjectId/OrganizationId очищают контекст и защищённые данные.
Сворачивание участников отменяет только их запрос; сворачивание задач — только их поиск.
Unload, Deactivate, Dispose, logout и offline отменяют текущие запросы всей карточки.
Проверка identity/token действует и для транспорта, который игнорирует CancellationToken.

Участники первоначально загружаются автоматически после обзора, как раньше; при повторе
используется отдельная команда. Задачи по-прежнему загружаются только явно и постранично.
Неподключённые разделы не создают сетевую нагрузку. Подтверждённые результаты не кэшируются
между сессиями или организациями. Постоянного offline-кэша и очереди записей нет.
