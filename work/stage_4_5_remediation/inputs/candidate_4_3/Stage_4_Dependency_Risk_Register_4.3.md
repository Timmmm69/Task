Риск не считается закрытым только потому, что PRD содержит mitigation.

## 3. Cross-cutting controls and escalation

- Contract drift invalidates field/operation traceability: package generation stops until Stage 2.3.1/3.5 references and 244-operation coverage are regenerated.
- Local server outage blocks shared writes: this is an accepted MVP trade-off; the client becomes explicit read-only and never queues business commands offline.
- Physical files can be unavailable or deleted outside the application: metadata recovery never claims to restore bytes.
- Permission mistakes are security defects: UI visibility is not an enforcement boundary, and a confirmed bypass escalates to the Security Architect immediately.
- Current status of OQ-001/OQ-003 is owned only by the synchronized Open Questions/Decision/PRD set; this register must not present an OQ simultaneously as fixed and an active blocking conflict.

## 5. Register lint and closure rule

For every `RISK-001…RISK-025`, Probability, Impact, Owner, Trigger, Preventive control, Contingency, Verification and Status are non-empty. `Closed with evidence` is permitted only when the verification named in the row has executed and its evidence is linked. Candidate 4.3 documentation controls do not substitute for Stage 4.4 independent re-audit or implementation/runtime evidence.
