# Продуктовая аналитика Task

Если задан проект PostHog, Task при первом открытии рабочего окна показывает разовое уведомление и автоматически начинает отправлять статистику. Уведомление не блокирует работу и позволяет сразу отключить сбор. Переключатель также доступен в Personal в разделе «Данные и фон», в Corporate — в разделе «Профиль». Отключение сохраняется для обоих режимов между запусками, отменяет отправку и удаляет локальный идентификатор установки и очередь. На компьютере остаётся только отметка об отказе. Уже принятые PostHog события остаются в соответствии с настройками хранения проекта.

Модель измеряет установки, участвующие в статистике. Один человек может пользоваться несколькими установками, а одну установку могут использовать несколько людей. Случайный UUID установки не связан с учётной записью, устройством или данными компании. Событие содержит только тип и время действия, версию, режим, UUID события, установки и сеанса, номер схемы и признак теста. Обогащение по GeoIP и создание профилей отключены. В проекте PostHog также должен быть включён **Discard client IP data**.

## Схема 1

| Событие | Когда считается |
| --- | --- |
| `app_opened` | Рабочее окно успешно показано, один раз на режим за процесс. Первый запуск учитывается после показа уведомления или после согласия в сборке, где оно требуется. |
| `task_created` | Создана задача, в том числе из входящей записи в Corporate. |
| `task_updated` | Подтверждено изменение основных полей задачи. |
| `task_planned` | Подтверждено изменение даты, времени, срока или длительности. Если тот же запрос изменил другие поля, считается одно действие. |
| `task_completed` | Подтверждён переход задачи в состояние «Завершена». |
| `calendar_event_created` / `calendar_event_updated` | Сохранено новое событие календаря или существенное изменение существующего. |
| `project_created` | Сохранён новый проект. |
| `inbox_item_captured` | Создана отдельная входящая запись в Corporate. Быстрая личная пометка создаёт задачу и учитывается в `task_created`. |

Повтор уже подтвердившейся идемпотентной операции, чтение, восстановление, уведомления и автоматическая генерация повторов исключены. Для Windows, запускающей несколько процессов с одним каталогом данных, первый владеет статистикой. Другие экземпляры продолжают работу без сбора, а настройка в них недоступна до перезапуска. Для отправки клиент использует [PostHog Capture v1](https://posthog.com/docs/api/capture-v1).

## Подключение

1. В настройках проекта PostHog скопируйте публичный **Project token**. Установите `TASK_POSTHOG_HOST` в `https://eu.i.posthog.com` или `https://us.i.posthog.com` по региону проекта и задайте `TASK_POSTHOG_PROJECT_TOKEN`. Для настроенного проекта Task используется EU. Клиент принимает только эти HTTPS-адреса и токен с префиксом `phc_`.
2. Установите переменные в окружении действующего процесса для локальной проверки либо в окружении сборки перед запуском обычного скрипта публикации. MSBuild запишет оба значения в метаданные исполняемого файла. Пакет и запуск сохраняют прежний формат. Значения окружения процесса имеют приоритет.
3. Для живой проверки используйте отдельный `TASK_DESKTOP_DATA_DIRECTORY` и задайте `TASK_POSTHOG_TEST=1` до запуска. Дождитесь уведомления (или включите статистику в сборке с обязательным согласием), выполните действие и проверьте событие в PostHog. Дашборд исключает такие события. Для рабочей установки оставьте `TASK_POSTHOG_TEST` незаданной.

Публикация без пары настроек оставляет отправку отключённой. Перед распространением определите допустимый для аудитории режим. Если нужно предварительное согласие, задайте `TASK_POSTHOG_REQUIRE_CONSENT=1` при сборке или запуске. При смене региона, токена или тестовой метки показывается новое уведомление либо требуется новое согласие. Ранее сохранённый отказ продолжает действовать. Секретный персональный ключ `phx_` предназначен только для создания дашборда и не должен передаваться клиенту или храниться в Git.

События записываются отдельно от SQLite и Corporate API. Очередь на диске ограничена 500 записями и семью днями. Запись заменяет целостный снимок и сохраняет UUID при повторе. Пакеты содержат до 20 событий. Временные ошибки и не подтверждённые по UUID элементы повторяются с задержкой, случайным разбросом и учётом `Retry-After`, до 24 попыток. Окончательные ошибки удаляют элементы из очереди. При переполнении приоритет у уже записанных событий. При аварии после отправки и до подтверждения возможен повтор с тем же UUID. Дашборд считает UUID один раз там, где считает события.

## Дашборд

Рабочий дашборд доступен в EU-проекте. [Task — Product Usage](https://eu.posthog.com/project/360552/dashboard/1140631)

Чтобы воспроизвести его в другом проекте, передайте в окружение `TASK_POSTHOG_MANAGEMENT_KEY` со scopes `dashboard:read`, `dashboard:write`, `insight:read`, `insight:write` и доступом к выбранному проекту. Запустите из `work/production`:

```powershell
pwsh -NoProfile -File deployment/desktop/Set-TaskPostHogDashboard.ps1 -PostHogHost https://eu.posthog.com -ProjectId <ID>
```

Скрипт добавляет отсутствующие карточки. `-DefinitionsOnly` отдаёт определения без обращения к PostHog. В рабочем проекте фильтр `mode` позволяет оставить `personal` или `corporate`. Строка `all` считает уникальные установки по выбранным режимам. Одна установка может входить в обе строки режимов, поэтому такие строки не суммируются.

- Воронка показывает долю установок, совершивших хотя бы одно полезное действие после открытия Task. Окно — последние 30 календарных дней UTC.
- Стадии считаются по истории, доступной в проекте. «Запустил» — действий ещё нет. «Попробовал» — 1–2 действия, включая хотя бы одно за последние 7 дней. «Начал использовать» — ≥3 действия в ≥2 дня за 7 дней. «Регулярно использует» — ≥5 действий в ≥3 дня за 7 дней. Остальные установки с полезной активностью попадают в «Активен ниже порога» или «Нет действий 7 дней». Последняя категория показывает паузу, которая может закончиться возвратом. Колонка «Активных дней из 7» показывает, сколько дней за неделю установки каждой стадии в среднем выполняли полезные действия.
- D1 и D7 — доли установок с полезным действием в точный календарный день после первого полезного действия. В знаменателе только когорты, для которых соответствующий день уже завершён.
- Даты в карточках заданы их определениями. Для сопоставимых стадий и первых действий оставляйте общий фильтр дат в положении «всё время».
