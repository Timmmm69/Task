# DESK-03 — рабочее содержимое основных разделов

Версия реализации: 1.0.0.

## Результат

Все восемь разделов из критерия `DESK-03` имеют production-содержимое после подтверждённого входа:
«Сегодня», «Календарь», «Проекты», «Каталог», «Контакты», «Уведомления», «Архив» и
«Настройки». Дополнительно подключена «Корзина», потому что она образует единый lifecycle-сценарий
с архивом и использует тот же готовый API-04 контракт.

Новые поверхности не используют локальный параллельный источник истины. Архив, корзина и настройки
загружаются через существующий authenticated executor; UI обновляется только из подтверждённого
ответа сервера.

## Архив и корзина

- `GET /api/v1/archive` и `GET /api/v1/trash` возвращают только объекты, разрешённые текущими
  capability и relation-политиками сервера.
- Архив явно отделён от завершённого статуса и корзины и остаётся read-only.
- Восстановление отправляет актуальный strong `If-Match`; сервер повторно проверяет lifecycle,
  object permission, parent и uniqueness invariants.
- Корзина сообщает, что удаляется metadata Task, а физические локальные и сетевые файлы не удаляются.
- `VERSION_CONFLICT`, `FORBIDDEN`, `OBJECT_NOT_VISIBLE`, завершение сессии и недоступность сервера
  переходят в контролируемые состояния без оптимистического удаления объекта из списка.

## Настройки

- Личные настройки и notification preferences читаются только с `Settings.ReadOwn` и сохраняются
  только с `Settings.UpdateOwn`.
- Настройки организации отображаются с `Organization.Read`; сохранение доступно только с
  `Organization.Update`.
- Изменения передают strong `If-Match` и idempotency key. Версия обновляется из authoritative
  ответа; конфликт не перезаписывает серверные данные.
- Клиент проверяет контрактные диапазоны, enum, время, выходные дни и связанные поля тихих часов
  до отправки запроса.
- Unsupported controls (avatar upload, внешние notification channels и urgency thresholds) не
  добавлены.

Release-сборка всего `Task.sln` проходит без ошибок. Полный source gate: 1650 passed, 0 failed,
4 skipped; пропущены только тесты, которым требуется отдельно предоставленный live PostgreSQL.
Desktop suite: 290/290. Тесты проверяют canonical URI, строгий DTO mapping, bearer/ETag/idempotency,
capability gates, восстановление и сохранение трёх групп настроек.

Новая миграция не требуется. Live PostgreSQL/API smoke на стенде заказчика и native Windows
UIA/Narrator walkthrough остаются deployment acceptance и не заявлены как выполненные локально.
