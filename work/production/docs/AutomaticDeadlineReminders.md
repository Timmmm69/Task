# Автоматические напоминания по сроку

При сохранении задачи со сроком Task создаёт одно управляемое напоминание через существующий сервис. В карточке рядом со сроком выберите «Напомнить»: выключить, 5/15/30 минут, час, день, в момент срока или свой интервал. Предварительный текст показывает местное итоговое время. Выбор «Не напоминать» сохраняется при обычном редактировании.

Новая задача использует «Напоминать за, мин» (15 по умолчанию). Значение фиксируется для конкретного получателя: изменение настроек не переписывает существующие задачи. Для даты без времени используется отдельно сохранённый час из настройки «Время напоминания для задач со сроком без времени» (09:00 по умолчанию). Это точка отсчёта интервала на указанную дату, а не скрытый deadline задачи; например, 15 минут до 09:00 — 08:45. Карточка прямо объясняет эту разницу. Такая задача остаётся непросроченной весь день. DST: пропуск переводится на первую допустимую минуту; при повторении часа выбирается ранний момент.

Personal доставляет владельцу локального хранилища. Corporate доставляет каждому текущему исполнителю, а без исполнителей — автору; нужны активная учётная запись и доступ к задаче. Наблюдатели не включаются. Интервал, отключение и отложенное время принадлежат отдельному пользователю; выбор в карточке Corporate меняет только его настройку. Настройки показа, звука, тихих часов и существующий журнал Windows применяются как раньше.

Изменение срока/исполнителей отменяет устаревшие срабатывания. Завершение, отмена, архив, корзина и удаление подавляют доставку. Восстановление активной задачи с будущим сроком возобновляет ещё не доставленное напоминание. Восстановление не меняет статус: завершённая/отменённая задача остаётся закрытой; существующая модель не разрешает её повторное открытие. Уже доставленная пара задача/получатель/время повторно не показывается. История сохраняется, включая окончательное удаление локальной задачи.

Если время напоминания уже прошло, а точный срок ещё впереди (либо дата срока — сегодня), новое/изменённое правило доставляется ближайшим проходом. Просроченные задачи не создают рассылку. Ручные правила не удаляются: совпадающее время объединяется на доставке, различные времена сохраняются. «Открыть», «Прочитано», «Отложить» работают через прежние действия; автоматическое правило отмечено в списке и редактируется через карточку.

## Обновление существующих данных

Personal: штатное резервное копирование и идемпотентная миграция SQLite 4 → 5; перенос выполняется при открытии локального хранилища. Corporate: серверный Migrator применяет migration 016 (15 → 16); согласование задачи и правил выполняется транзакционными триггерами. Настройки не хранятся в общем JSON задачи. Прямо назначенные ограниченные runtime-роли получают доступ к новым таблицам/функциям через миграцию; стандартный grant-runtime.sql также обновлён. Не использовать API собственных напоминаний для изменения чужих настроек.

Активные задачи с будущим сроком получают правило. Имеющиеся ручные правила «До срока»/«В срок» учитываются; отменённое такое правило переносит явное отключение. При первичном переносе уже прошедшее время срабатывания подавляется, чтобы не вызвать лавину; изменение срока/индивидуальной настройки снимает это подавление. Просроченные задачи, сроки и история не переписываются. Неизвестный часовой пояс старой даты без времени не угадывается. Серверный фоновый обход ограничен размером пакета и проходит задачи по очереди; повторный запуск безопасен.

## Передача и проверка

Клиент 1.0.10 собирается штатным Build-UnsignedPortableClient.ps1 и проверяется Test-UnsignedPortableClient.ps1. Это unsigned portable пакет для пилота; он не заменяет подписанный канал production-обновлений. Сервер требует обновлённые API, Worker и Migrator и PostgreSQL 16+. PostgreSQL 15 штатно отвергается до DDL.

Подробные фактически выполненные проверки и ограничения содержатся в outputs/20261014_task_automatic_deadline_reminders_1.0.0/validation-report.md. Принятый Windows запрос не является визуальным подтверждением баннера.
