# Task 12.3 — компании и контактные лица

Версия: 12.3.0. Ветка: `feature/crm-contacts-workspace`. База: `8764a51` (12.2), включая `935e479` (12.1).

Компании доступны кнопкой «Компании» внутри существующего корпоративного раздела «Контакты». Личные контакты сохраняют прежний экран и модель. Новый верхнеуровневый маршрут не вводится.

## Реализованные сценарии

- Серверный список, поиск по `q`, cursor-пагинация, загрузка, пустой результат и ошибки. Выбор сохраняется при обновлении; компания вне текущей страницы повторно проверяется по GET. Отозванный доступ очищает карточку и выбор.
- Карточка с названием, юридическим названием, отраслью, сайтом, налоговым идентификатором, заметками и бизнес-статусом. Создание, редактирование, отмена. Изменение бизнес-статуса не меняет lifecycle.
- Strong If-Match/ETag, проверка увеличения версии, единый запрет параллельных мутаций, сохранение ввода при ошибках и конфликте. Неопределённый результат PATCH/изменения связи требует перечитывания перед повторной записью.
- Повтор POST создания после неопределённого результата использует прежние payload и Idempotency-Key; форма заморожена до подтверждения, валидационной ошибки или отмены. Повторное нажатие во время запроса не создаёт второй запрос.
- Контактные лица: существующий серверный поиск контактов по имени с пагинацией, дополнительный GET для проверки доступности, POST привязки и DELETE связи. Поля связи: должность, подразделение, основной контакт, даты начала/окончания. Дубликаты не добавляются оптимистически; после ответа сервера перечитывается компания.
- Список связанных лиц содержит только контакты, доступность которых подтверждена отдельным GET. Имена из данных связи не предполагаются; чтение деталей выполняется пакетами до четырёх запросов. Смена выбора, прав, сессии и отмена запроса защищены generation/token-проверками.
- Открытие контакта использует существующую карточку 12.1–12.2. Возврат кнопкой «Компании» сохраняет выбор и повторно проверяет доступность. Открытие связанного контакта во время редактирования компании отключено.
- Глобальный поиск открывает `company` через существующий `MainWindowViewModel.OpenWorkObjectAsync` и раздел `contacts`.
- Серверный DELETE связи дополнительно проверяет доступность активного контакта в текущей организации и его Contact.Read object-scope, как POST. При отказе связь и версия компании не меняются.

## API и права

| Операция | API | Permission / предусловия |
| --- | --- | --- |
| Список, карточка | GET `/api/v1/companies`, `/companies/{id}` | Contact.Read и object-scope |
| Создание | POST `/api/v1/companies` | Contact.Create, Idempotency-Key |
| Изменение | PATCH `/api/v1/companies/{id}` | Contact.Update, object-scope, strong If-Match |
| Поиск/проверка контакта | GET `/api/v1/contacts?q=…`, `/contacts/{id}` | Contact.Read и независимый object-scope контакта |
| Привязка | POST `/api/v1/companies/{id}/contacts` | Contact.Update компании, Contact.Read контакта, strong If-Match компании, Idempotency-Key |
| Удаление связи | DELETE `/api/v1/companies/{id}/contacts/{childId}` | Contact.Update компании, Contact.Read контакта, strong If-Match компании |

Право записи требует активного корпоративного экрана, сессии, подключения, нужной capability и активного lifecycle компании. Сервер остаётся источником object-level authorization. Обрабатываются 401/403/404/409/412/422, offline, malformed response, отмена и поздние ответы. Сервер не раскрывает имена недоступных контактов через связи.

## Ограничения контракта

- Название: 1–500 после trim; юридическое название ≤500; отрасль ≤200; сайт ≤2048; налоговый идентификатор ≤100; заметки ≤20000; status: active/inactive. URL — абсолютный HTTP(S) без credentials, по правилу существующего `ValidateContent` сервера.
- Должность/подразделение ≤200; даты `yyyy-MM-dd`, окончание не раньше начала. company_contacts — отдельная связь с составным ключом, а не новая запись контакта.
- Поиск компаний API ищет по названию/заметкам; отдельные фильтры по реквизитам не добавлены. Cursor привязан к запросу и области доступа.
- PATCH связи отсутствует. Изменять уже созданные поля связи отдельным запросом нельзя; фиктивный PATCH не введён. Адресов компаний, сделок, счетов, воронки, взаимодействий, новых API и миграций нет.
- Удаление связи не удаляет контакт. Скрытый/неактивный contact в link/unlink даёт существующую generic validation error без раскрытия данных.
- Ключ создания сохраняется в рамках текущей формы и её повторных попыток; восстановление незавершённой формы после перезапуска приложения не входит в данный контракт.
